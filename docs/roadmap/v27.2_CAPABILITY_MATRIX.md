# 🗺️ Nexus v27.2 演進藍圖：能力矩陣與模組化擴張 (Capability Matrix)

## 📌 戰略定調 (Strategic Intent)
Nexus v27.1 已成功確立了具備 `CI Gate`、`Receipt-Driven Promotion` 與 `Atomic Rollback` 的「治理底座」。
**v27.2 的核心目標不是「繼續優化原版」，而是「用題庫來規劃新版本的能力邊界」。**

我們將摒棄「一波流解完 113 題」的巨石模式，轉而將題庫拆解為不同的「能力家族 (Capability Families)」，並依循 **Clean Architecture** 與 **Canary Release** 的最佳實務，逐族進行 TDD 擴張。

---

## 🧩 1. 題庫能力分群 (Taxonomy & Clustering)

不再把 113 題視為單一坑，而是按其本質能力劃分為四大執行線：

### A. 治理與規格線 (Governance / Spec)
*   **涵蓋範圍**: ADR 凍結、Manifest 准入、Diff Gate、Audit Trail。
*   **特性**: 只做規格與證據，不碰代碼修復。目標是「穩定」而非「聰明」。
*   **優先級**: **P0** (共用底座)

### B. 研究與路由線 (Research / Routing)
*   **涵蓋範圍**: 題目意圖理解、失敗模式拆解、候選策略評分、路由決策。
*   **特性**: 負責回答「這題該怎麼處理」，是所有解題能力的入口分發器。
*   **優先級**: **P1**

### C. 修復與合成線 (Repair / Synthesis)
*   **涵蓋範圍**: AST 語法修復、Patch 補丁合成、Refusal Recovery (拒絕回應修復)。
*   **特性**: 直接擴展核心解題能力，最容易發生破壞性副作用。
*   **優先級**: **P1**

### D. 觀測與運營線 (Observability / Ops)
*   **涵蓋範圍**: Heatmap、Trend Line、Canary Rollout、Dashboard。
*   **特性**: 讓系統具備自省與運營能力，確保新能力上線的效益可被量化。
*   **優先級**: **P2**

## 🛠️ 2. 十大執行里程碑 (The 10 Milestones)

### Phase 1: 盤點與抽象 (Foundation)
- [ ] **M1. 題庫盤點 (Taxonomy Mapping)**: 將 113 題標註對應的 Capability Family、輸入輸出與失敗模式，產出 `topic_taxonomy.md`。
- [ ] **M2. 共用能力抽象 (Common Core)**: 確保 Evidence Sealing、Replay Verification、Diff Gate 等底座已完全解耦，成為後續新題的唯一依賴 (Inner Core)。

### Phase 2: 獨立演進 (Decoupled Evolution)
- [ ] **M3. 治理線擴張**: TDD 實作 ADR 版本化與 Audit Trail 的進階查詢。
- [ ] **M4. 路由線擴張**: TDD 實作題目拆解器與 Evidence Quality 評分器。
- [ ] **M5. 修復線擴張**: TDD 實作 AST Patch 合成器 (先挑 3-5 題代表題驗證)。
- [ ] **M6. 運營線擴張**: 將新能力的失敗模式接入 Blocker Heatmap 追蹤。

### Phase 3: 受控放量與封板 (Controlled Rollout)
- [ ] **M7. 逐族擴張 (TDD Loop)**: 每個題型家族嚴格遵守「紅測試 -> 最小實作 -> 抽共用件 -> 批量推進」的節奏。
- [ ] **M8. Canary 放量**: 新題型先進入 `migration` 車道 (10% Rollout)，觀測無 Regression 後再人工晉升。
- [ ] **M9. Metrics 閉環**: 將 Canary 階段的 Rejection Receipts 回寫至「學習矩陣」，形成防再發規則。
- [ ] **M10. v27.2 凍結 (Version Sealing)**: 當特定題型家族穩定後，發布新版 ADR 並凍結該版本的 `manifest_hash`，絕不回頭污染 v27.1 的歷史基線。
