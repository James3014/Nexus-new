# Nexus v27.5 Problem-Oriented Governance Platform Plan

本計畫旨在將 Nexus 從「族群量產」提升至「控制平面 (Control Plane)」級別，實現 **問題接入標準化 + Policy-as-Code**。

---

## 🏗️ 核心分層架構 (SoC)

| 層級 (Layer) | 職責 (Responsibility) | 關鍵組件 |
| :--- | :--- | :--- |
| **Problem Ingress** | 標準化任何 Code Problem 為 `ProblemTicket` | `TicketFactory` |
| **Classification** | 判定 Problem Class 與 Domain Lane | `ProblemClassifier` |
| **Policy Engine** | 集中評估 Admission, Override, Canary 等政策 | `PolicyEngine` |
| **Execution Lanes** | 統一介面執行的領域專家 (Django, Astropy, etc.) | `BaseLane` |
| **Evidence Fabric** | 統一收據、Replay 與 Seal 格式 | `EvidenceFabric` |
| **Observability** | 提升至治理級指標 (Rollback Rate, Fidelity) | `GovernanceMetrics` |
| **Release Plane** | 控制 Plane 服務化 (Canary, Freeze) | `ReleaseControlPlane` |

---

## 🎯 十大里程碑 (Milestones)

- [ ] **M1. Problem Contract 標準化**: 定義全系統唯一的 `ProblemTicket` DTO。
- [ ] **M2. Problem Classifier 抽離**: 升級路由為「類別 + 領域」兩段式。
- [ ] **M3. Policy Engine 化**: 消滅內嵌於 Verifier/Writer 的政策硬編碼。
- [ ] **M4. Execution Lane 標準介面**: 統一 `plan`, `guard`, `execute`, `verify` 介面。
- [ ] **M5. Evidence Fabric 統一**: 所有產線產出同型別的 Evidence Bundle。
- [ ] **M6. Observability 升級**: 實作 `governance_metrics.py`。
- [ ] **M7. Release Control Plane**: 將 Canary/Freeze 提升為 Service。
- [ ] **M8. General Problem Lane**: 實作處理通用問題的專家車道。
- [ ] **M9. Refactor & Evolution Lane**: 專門處理結構優化與技術債清理。
- [ ] **M10. v27.5 Freeze**: 產出最終控制平面指紋。
