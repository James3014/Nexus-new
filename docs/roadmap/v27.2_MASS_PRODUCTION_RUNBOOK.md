# 🏭 Nexus v27.2 批量量產與導入指南 (Mass Production Runbook)

## 📌 戰略定調
Nexus v27.2 的「框架層」已完成 (Framework-Complete)。接下來的目標是將 125 題 (113 SWE + 10 Concurrency + 2 Experimental) 以 **「按族群批量 (5 題/批)」** 的方式灌入產線。

每批次必須嚴格通過觀測 (Metrics)、金絲雀放量 (Canary Rollout) 與特徵旗標 (Feature Flag) 的閘門。任何一批發生 `replay mismatch`、`critical blocker` 或 `stress flake`，產線立即停線 (Fail-Closed) 進行底座修復。

> **⚠️ 安全警示：DCL (Double-Checked Locking) 降級通報**
> `Double-Checked Locking` 雖在 Concurrency 初始驗證中出現，但因其在某些記憶體模型下的高風險，被列為 **「受控特例工具」**。嚴禁將其擴散為全域預設模式；任何使用皆需綁定 Contract Tests 與 Stress Tests 證明其必要性。

## ⚙️ 單批次固定執行流 (Per-Batch Workflow)
每當 Agent 接到 `執行 BXX 批次` 指令時，必須強制走完以下 6 個步驟：

1. **題目分流 (Routing)**：使用 `route_planner` 產生 `Confidence Receipt`。
2. **紅測試 (TDD: Red)**：為這 5 題建立帶有 Invariant (不變量) 或 Stress (壓力) 的紅測試。
3. **最小防護 (TDD: Green)**：只寫最小 guard/adapter，絕對不提前做過度泛化。
4. **抽共用件 (Refactor)**：若有重複邏輯，提煉至 `common_core`。
5. **證據聚合 (Evidence Sink)**：產出本批次的 Evidence Seal、Replay 結果、Family Metrics 與 Ranking Scorecard。
6. **灰度放量 (Canary Gate)**：將新題型以 Observation-Only 模式觀察，穩定後才寫入 Baseline Manifest。
