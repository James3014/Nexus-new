# 2026-03-18 工作區搬遷規劃（Downloads -> Workspace）

## 背景與目標
- 目前主工作區位於 `~/Downloads`，已出現權限彈窗頻繁、索引範圍過大、路徑誤觸等風險。
- 目標：在不中斷現有進度下，將 Nexus 工作流平滑遷移到 `~/Workspace`，並保留可回滾能力。

## 為何不建議直接用 `~/Downloads` 當工作區
1. 目錄噪音高：下載暫存檔多，會增加搜尋與索引負擔。
2. 權限彈窗頻率高：跨路徑存取機率高，容易卡在授權流程。
3. 誤操作風險高：清理下載資料時容易誤刪專案檔。
4. 多代理協作不穩定：工作邊界不清，輸出路徑容易混淆。

## 搬遷時機（必須在 checkpoint 後）
符合以下條件才進行搬遷：
1. 當前任務完成一個里程碑（有文件或 benchmark 輸出）。
2. 無長時間任務在跑（benchmark/test/agent loop 已停止）。
3. 可接受 5-10 分鐘搬遷與驗證窗口。

## 五階段搬遷流程

### Phase 1：凍結規則（不搬檔）
1. 新工作規則先確立：未來工作目標路徑為 `~/Workspace/nexus`。
2. 當前仍在 `~/Downloads/Muse-Nexus` 的任務先做完，不中途改路徑。

### Phase 2：建立新骨架
1. 建立目錄：
- `~/Workspace/nexus`
- `~/Workspace/_agents/skills`
- `~/Workspace/_bin`
2. 僅建立結構，不修改現有專案內容。

### Phase 3：搬核心專案（先複製，不刪除）
1. 將 `~/Downloads/Muse-Nexus` 複製到 `~/Workspace/nexus`。
2. 不刪除舊目錄，保留完整回退點。
3. 在新路徑執行最小驗證：
- `git status`
- `uv run scripts/ops/ci_gate.py`
- 讀取 `docs/INDEX.md` 正常

### Phase 4：觀察期（24 小時）
1. 只在新路徑執行任務。
2. 觀察三件事：
- 權限彈窗是否明顯下降
- 指令與輸出路徑是否穩定
- benchmark/gate 是否與舊路徑一致

### Phase 5：清理舊副本
1. 觀察期穩定後，才清理 `~/Downloads` 舊副本。
2. 清理前再次確認新路徑有最新輸出與文件。

## 風險與回滾方案

### 主要風險
1. 新舊路徑混用，導致輸出檔案分散。
2. 腳本內硬編碼路徑指向舊位置。
3. 搬遷中斷導致 agent session 上下文錯位。

### 回滾策略
1. 回滾條件：
- `ci_gate` 失敗且短時間無法修復
- 主要流程在新路徑無法啟動
2. 回滾動作：
- 立刻改回 `~/Downloads/Muse-Nexus` 啟動
- 新路徑保留，待修復後再切換
3. 因為採「先複製不刪除」，回滾成本低。

## Skills 與多代理管理建議
1. 中央技能庫：`~/.agents/skills`
2. 工作區技能副本：`~/Workspace/_agents/skills`
3. 建議採同步（rsync/cp）而非 symlink，降低授權卡死機率。

## 啟動 SOP（10 行）
1. `cd ~/Workspace/nexus`
2. 確認當前路徑正確（不要在 `~/Downloads`）
3. 同步 skills 到工作區副本
4. 啟動 agent
5. 先讀 `docs/INDEX.md`
6. 依 INDEX 順序執行，不跳階段
7. 每個里程碑先回報 gate 與證據路徑
8. 如需破壞性操作再提問
9. 若卡授權彈窗，優先 `Allow This Conversation`
10. 當輪結束後更新對應 docs 與 INDEX
