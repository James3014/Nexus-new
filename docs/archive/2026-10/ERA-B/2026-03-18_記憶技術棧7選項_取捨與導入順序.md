# 2026-03-18 記憶技術棧 7 選項：取捨與導入順序

## 決策原則
先做「可用、可驗證、低耦合」；再做「更聰明、更大規模」。

## 7 選項取捨（決策版）
1. 立即採用（Now）
- QMD
- LanceDB
- LCM / lossless-claw（核心機制）

2. 延後觀察（Later）
- BrainX（先做最小矛盾檢測，不一次導入全套）

3. 條件式採用（Conditional）
- Vertex AI Memory Bank
- Nowledge Mem
- 觸發條件：需要跨團隊/跨 Agent 大規模共享，且本地維運成本過高。

4. 暫不採用（Not Now）
- OpenViking
- 原因：底層變更面過大，會干擾現階段重構與治理穩定性。

## 導入順序（必照順序）
1. Phase A：LanceDB 成為穩定記憶主幹
- 打通 runtime 與主流程檢索。
- 建立 episodic / semantic / policy 三層索引。

2. Phase B：加 LCM（lossless）
- compaction 前後做 coverage/checksum 驗證。
- 防止摘要壓縮造成關鍵細節遺失。

3. Phase C：最小矛盾檢測（BrainX-lite）
- 先規則式矛盾檢測（facts/constraints 衝突）。
- 通過後再評估是否升級到完整 BrainX。

4. Phase D：雲端記憶外包評估
- 只在明確成本/維運壓力下評估 Vertex/Nowledge。

## 驗收指標（每階段）
1. Memory Hit Precision
2. Negative Transfer Rate
3. Replay Consistency
4. Token/Latency ROI

## 一句話策略
先把 LanceDB 做成穩定記憶主幹，再疊加 lossless 與矛盾檢測；雲端外包與底層大改放後面。
