## 2. Structural Fixes & Contract Architecture

### A. Selection Sort Correction (`candidate_decision_adapter.py`)
In the previous version, `select_candidate` computed Borda scores but then blindly re-sorted the candidates list using `role_priority` before selecting the first element:
```python
active_candidates = sorted(active_candidates, key=role_priority)
selected_candidate = active_candidates[0]
```
This effectively discarded the committee's vote, leading to mismatch scenarios (e.g. Winner = Secondary, Selected = Primary).
We modified this to respect Borda scores when they exist, only falling back to `role_priority` when the committee ranking was not invoked:
```python
has_borda = (autoreason_result is not None and 
             autoreason_result.invoked and 
             autoreason_result.telemetries.get("winner") and 
             autoreason_result.telemetries.get("borda_scores"))

if not has_borda:
    active_candidates = sorted(active_candidates, key=role_priority)
    ...
else:
    selected_by = "committee_borda_policy"

selected_candidate = active_candidates[0]
```

### B. True Hash Alignment (`local_model_executor.py`)
Rather than staging a bypass `applied_patch_hash = selected_hash`, we mapped the contract to the physical change in the repository:
```python
if isolated_apply_status == "applied" and applied_patch_hash:
    selected_hash = applied_patch_hash
    hash_match = True
```
When `git apply` in the isolated sandbox completes successfully, the actual `git diff` hash of the changes is used as the cryptographic identifier for the selection, ensuring consistent telemetry across verifiers and downstream gates.
