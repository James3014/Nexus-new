## 範圍 A：Abort Receipt Guarantee

**問題**：T1.2/T1.3 發現 3 個 task 沒有 receipt，原因是 workspace provisioning 失敗時沒有產出 abort receipt。

**解法**：新增 `nexus/evidence/abort_receipt.py`，定義 `AbortReceipt` dataclass，即使 workspace 失敗也必須寫 abort receipt。

**6 種 workspace failure subclass**：
1. `REPO_NOT_MOUNTED` — repo 目錄不存在
2. `WORKSPACE_NOT_WRITABLE` — 目錄存在但無法寫入
3. `TARGET_PATH_UNRESOLVED` — 目標路徑無法解析
4. `MANIFEST_MISSING_TARGET` — manifest 找不到目標
5. `WRONG_REPRO_PATH` — reproduce 路徑錯誤
6. `STALE_MODEL_PATH` — model path 已過時

**關鍵**：workspace failure 記為 `failure_class=workspace_provisioning`，不算 patcher failure。

## 範圍 B：Dedupe Rule

**問題**：`astropy-14096` 和 `astropy__astropy-14096` 是同一個 task 的 alias，但目前系統視為不同。

**解法**：
- `normalize_instance_id()` 統一格式：`astropy__astropy-14096` → `astropy-14096`
- `DedupeManifest` 儲存 canonical ↔ alias 對應
- `find_canonical()` 用 manifest 查找正確的 canonical ID
- 不改歷史 receipt 原文，只產出 derived manifest
