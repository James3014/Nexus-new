## 🏛️ 核心架構哲學 (The Master Blueprint)

### 1. 母系統範式 (Diana Hu - Mother System)
*   **AI 是作業系統**：Nexus 不只是 Copilot，而是所有決策、流程、回饋的控制平面。
*   **全組織可查詢 (Queryable)**：整個系統必須對 AI 清晰可讀。每一項行動必須產出 Artifact (證據) 與 Lineage (譜系)。
*   **Parent-Child 結構**：Nexus (Parent) 為子產品 (Children) 提供共用的 Context, Memory 與 Governance。

### 2. 啟發式自癒 (HL / HS Plan)
*   **更新軟體結構，而非僅權重**：優化的重點是 Policy、State Detectors 與 Tests 的演化。
*   **失敗驅動更新**：將「失敗軌跡」視為系統進化的最昂貴燃料。
*   **壓縮歷史**：規則必須具備生命週期（Active → Deprecated → Retire），防止系統因規則通脹而失控。

### 🛡️ 實體執行硬閘 (The Hardening Gates)

### 3. 誠信防禦 (Meta ACH - Mutation Assurance)
*   **懷疑自己的成功**：僅有測試通過是不夠的。必須執行 **Mutation Testing (突變測試)**。
*   **殺死突變體 (Mutants)**：一個有效的測試案例，必須能偵測並「殺死」故意製造的語義缺陷。
*   **門禁規則**：若突變體存活 (Survived)，則判定為 `UNVERIFIED_BLIND_SPOT`，禁止公開 Claim。

### 4. 外骨骼感測 (91APP - Harness Engineering)
*   **前饋 (Feed-forward)**：在 `Plan (P)` 階段執行 `Preflight Sensor`，核驗線路與環境是否 Ready。
*   **回饋 (Feedback)**：實作 `Semantic Failure Sensor`。失敗時不准盲目重試 (Blind Retry)，必須產出「說人話」的診斷與修正建議。
*   **BDD 驗收**：使用 `Given-When-Then` 驗證商業價值，補齊單元測試無法驗證的需求正確性。

### 📈 數據與效能治理 (The Efficiency Engine)

### 5. 數據工程對位 (Data Engineering Book)
*   **數據資產化**：將每一次執行軌跡 (Episode) 轉化為具備語義標籤的認知資產。
*   **Token RoI Monitor**：監控「每一塊錢 Token 換取的解決率增量」。
*   **遙測硬化**：遙測數據必須具備 Lineage (溯源)。嚴禁使用 `estimated` 數據誤導成本決策。

### 6. 自我生產與過濾 (Autodata)
*   **強弱模型差距 (Gap Analysis)**：自動生成能暴露裸模弱點、但能證明 Nexus 價值的鑑別力樣本。
*   **數據飛輪**：從失敗案例自動生成 DataForge 任務，實現「一人受難，全機群進化」。
