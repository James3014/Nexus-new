# Nexus v27.1 自動化晉升 (Auto-Promotion) 研發支線

本文件定義了 v27.1 研發階段的任務拆解與完成標準。

## 🎯 階段目標
實現「收據驅動」的無人值守晉升管線，鎖定 Nexus 的自治演化能力。

---

## 🛠️ Sprint 1: 收據與決策引擎硬化 (Week 1)
- [ ] **[P0] 收據 Schema 升級**: 補齊 `RejectionReceipt` 及其 blocker taxonomy。
- [ ] **[P0] 決策引擎重構**: 實施 ADR-0011 定義的自動化分層邏輯。
- [ ] **[P0] 候選排序實作**: 依據 ADR-0012 實施基於證據品質的確定性排序。
- [ ] **[P1] Replay 驗證器**: 建立 `ReceiptReplayer`，驗證收據與決策的一致性。

## 🚀 Sprint 2: CI 閘門與物理鎖定 (Week 2)
- [ ] **[P0] Drift Stop 實作**: 將 `manifest_hash` 雜湊檢查接入晉升入口。
- [ ] **[P1] 原子回退機制**: 模擬資料寫入失敗，驗證治理鏈的原子性。
- [ ] **[P1] CI 核心接入**: 將 `ci_gate_sim.py` 的邏輯正式掛載至 GitHub Actions 模擬流。
- [ ] **[P2] 治理看板對接**: 將 `metrics_collector` 的輸出連動至 `NEXUS_UNIVERSAL_MASTER_REPORT`。

---

## 🏁 完成標準 (Definition of Done)
1. **P0 測試 100% 綠燈**: 包含 Manifest 鎖死、晉升收據驗證與 Drift 攔截。
2. **具備物理收據**: 任何晉升決策皆有對應的 `.json` 收據可供審計。
3. **無人值守驗證**: 在 `migration` 車道投入新題庫，系統能自動判定是否可晉升。
