# Nexus Release Gates & Branch Protection

This document defines the mandatory gates that must be passed before merging code or releasing new versions of Nexus.

## 🚦 Merge Gates (PR)

All Pull Requests to `main` or `master` must satisfy:

1. **Pytest Collect (P0)**: Suit must be discoverable.
2. **Changed-Files Lint (P1)**: No logic or style errors in touched Python files.
3. **Dependency Sync**: `uv lock --check` must pass.
4. **No Direct Push**: Workflows must not contain `git push` to protected branches.

## 📦 Release Blockers

The following conditions will block a release:

- **Dirty Worktree**: Uncommitted changes in submodules (e.g., `.tmp_build`).
- **Unexplained Deletions**: Files deleted without clear rationale in the PR/Commit message.
- **Unverified Claims**: Public README/PRD claims without machine-verifiable evidence.
- **Stale Receipt Trail**: Failure to generate capability receipts for core engine changes.

## 🛠️ Branch Protection Rules
- Require linear history.
- Require status checks to pass before merging.
- Disable direct force-push to `main`.

## 🌙 Artifact-Only Automation
Workflows like `Night Shift` and `Benchmark CI` are configured as **Artifact-Only**. They produce `.patch` files or `.jsonl` reports which must be manually reviewed and merged via the standard PR process. **Direct auto-commits are strictly forbidden.**

## 🔭 Live Gateway Source Drift Check (#1900)
Owner decision (#1900, 2026-10-12): the live MCP Gateway may run only commits published on GitHub `main`, or an exact head of an open/merged PR during a bounded rebind. `scripts/ops/check_gateway_source_drift.py` is a **read-only** detector for that rule. It reads `http://127.0.0.1:8766/health`, finds the newest ancestor of the loaded `git_head` on `origin/main` (it runs `git fetch origin main` in `--repo`, or uses `--main-ref` without fetching), and reports `GATEWAY_SOURCE_UNPUBLISHED(n)` (ALERT; an unpublished loaded head where at least one unpublished commit touches a path outside `tasks/` — the JSON lists the touched paths) or, when EVERY unpublished commit touches only `tasks/` paths (Owner refinement, #1900, 2026-10-13: a merge commit is judged by its diff against its first parent), the INFO `GATEWAY_BIND_ONLY_LOCAL_COMMITS(n)` (exit 0, still lists the paths; root cause tracked in #1939), and `GATEWAY_BEHIND_MAIN(n)` (WARN when more than 50 commits or more than 7 days behind; below that, OK). An unreachable or malformed health payload fails closed (`GATEWAY_HEALTH_UNREACHABLE` / `GATEWAY_HEALTH_MALFORMED`). Exit codes: 0 OK/INFO, 1 WARN/ALERT, 2 probe failure. Run it with `python scripts/ops/check_gateway_source_drift.py --repo <Nexus-new clone> [--json] [--offline]`; `--report-issue 1900` (only when passed explicitly) creates or edits one comment tagged `<!-- GATEWAY_DRIFT_REPORT -->`. To schedule it, an operator may add a user LaunchAgent whose `ProgramArguments` run that command with `--report-issue 1900` and a `StartInterval` (for example 21600 seconds), `StandardOutPath`/`StandardErrorPath` under `~/Library/Logs/`; agents must not install it themselves. The check never reloads or rebinds the Gateway: the #2153 auto-deployer is the routine remedy and needs no Owner activation (see Gateway Deploy Authority below).

## 🚀 Gateway Deploy Authority (#2155)
Owner decision (2026-10-14, #2155): routine MCP Gateway deploys need no Owner activation. The health-gated auto-deployer `scripts/ops/nexus_gateway_auto_deploy.py` (#2153, LaunchAgent `com.nexus.gateway-auto-deploy`) deploys published `main` once its required checks are green, probes the candidate on a spare port, switches the plist, probes the live port and rolls back on failure. Its authority is the green published commit, and its record is `~/.local/state/nexus-gateway-auto-deploy/receipts.jsonl`. While any governed task is in flight (`IN_PROGRESS`/`ACTION_REQUIRED`, or a task state that cannot be read), the deployer defers the switch (`DEFERRED_TASKS_IN_FLIGHT`, #2227), because a switch moves the Controller HEAD those tasks are bound to. After 6 h it posts one warning on #2227 naming the tasks. It never forces the switch; a manual `run --allow-in-flight` is the only override. Each deployment `deployments/a1-<sha>` gets its own Controller worktree `controllers/a1-<sha>` (exported as `NEXUS_CANONICAL_SOURCE_ROOT`), so Task Card bind commits never land in the running deployment (#1939); bound cards are carried byte for byte to the next Controller. The rendered Gateway command also exports `NEXUS_AGY_RUNTIME_AUTHORIZED=1` after sourcing `mcp-gateway.env`, so `nexus_worker_candidate`'s default Agy route passes worker preflight (Owner approval, #2318); it never exports the broader `NEXUS_EXTERNAL_RUNTIME_AUTHORIZED`. A crash restart is launchd `KeepAlive` on the deployed plist: the deployer keeps the previous plist's `KeepAlive`/`RunAtLoad` keys and only rewrites `ProgramArguments`/`WorkingDirectory`. It reads no receipt. The #526 owner-activation / BREAK_GLASS host-effect and R1 recovery receipts (`nexus/contracts/gateway_deployment.py`) now guard only the manual emergency path, so their expiry blocks only that path, never a routine deploy or a restart.

Required-check changes (#2402): the deployer binds each required check name to its own workflow (`REQUIRED_CHECKS`) or knowingly skips a PR-head commit status (`PR_HEAD_STATUS_CONTEXTS`), and a name it knows neither way stops the deploy (`UNKNOWN_REQUIRED_CHECK`). When main also carries a deployer that knows the new name, the running deployer updates only itself: the candidate must be on GitHub `main`, its deployer source (read from the commit and parsed with `ast`, never imported) must know every unknown name, and every required check the running deployer can bind, plus its floor checks, must be green on the candidate. Then the `auto-deploy-current` link moves to `deployments/a1-<sha>` after the same selftests a deploy runs, and the receipt says `DEPLOYER_SELF_UPDATED` (a failed selftest is `DEPLOYER_SELF_UPDATE_REFUSED`, capped at 3 tries per candidate). The Gateway plist is not touched; the next cycle's new deployer applies the full gate and deploys as usual. A name that no deployer on main knows still fails closed, and a link already at the candidate is never moved again. So a change to the required-check set no longer needs an Owner reinstall of the LaunchAgent, as long as the PR that teaches the deployer the new name merges.

Manual emergency path (only when the auto-deployer cannot recover the Gateway):
1. `hold`: run `python scripts/ops/nexus_gateway_auto_deploy.py hold --reason "manual #526 rebind"`, which writes the HOLD file the LaunchAgent honours. `NEXUS_GATEWAY_AUTO_DEPLOY_HOLD=1` only affects a process that inherits it, and the installed LaunchAgent does not. Under HOLD the deployer still finishes or rolls back a half-done switch left by a crash (`pending-switch.json`), so before rebinding, wait until `status` shows no pending switch. A cycle that is already running cannot interleave: the deployer re-checks HOLD under the #526 manager lock right before any plist write, and the manual rebind takes that same lock.
2. Manual rebind: a #526 governed rebind or R1 recovery through `scripts/ops/mcp_gateway_durable.py`, with a fresh Owner activation and receipt. An expired receipt fails closed here.
3. `adopt`: run `python scripts/ops/nexus_gateway_auto_deploy.py adopt` to record the manually written plist, so the deployer does not treat it as `FOREIGN_PLIST`.
4. `release`: run `python scripts/ops/nexus_gateway_auto_deploy.py release` to resume routine deploys.

## 🔁 Workforce Model Auto-Update (#1996)
Owner decision (#1996 option A, 2026-10-13): when Agy serves a newer model in the same family and tier as a Workforce default, or stops serving the default, `scripts/ops/workforce_model_autoupdate.py` switches the default automatically, but nothing merges until an independent AI reviewer ACCEPTs the exact PR head. Stages: discover (`agy models`, catalog fetch only; ids must match `gemini-<maj>.<min>-flash-<tier>` with the deterministic label, everything else is recorded and ignored) → decide (NOOP / SWITCH / BLOCKED; never crosses provider, family or tier, never downgrades, never raises autonomy) → attest (one leased `--mode plan --sandbox --model <id>` call with the no-tools prefix through `scripts/bench/agy_provider.py`; needs `NEXUS_AGY_ACCOUNT_ALLOWLIST`; observed id and backend label must match exactly) → render (surgical yaml edit, dict cross-check, real `WorkforcePolicyLoader`) → nexus-runtime PR → review (isolated `claude -p`: pinned model, `--tools ""`, `--strict-mcp-config`, `--setting-sources ""`, plan mode, empty temporary cwd, exact diff inline; strict JSON verdict posted on the PR with reasons sanitized and length-capped because both repos are public; any failure is REJECT) → merge (recorded ACCEPT + all required checks green on that head, no required checks = blocked + a deterministic scope guard: the head is the SHA this tool pushed, the changed files are exactly the scope list, every file's bytes at that head equal the rendered bytes, and main is still the base it was built on, otherwise the tool rebuilds once on the new main and re-reviews + optional `--pre-merge-hook <cmd>` printing `GO`, `--match-head-commit`; a head the tool did not author is never merged) → Nexus-new pin + byte-identical mirror PR and trusted-anchor PR (anchor merges first, then the tool rebuilds the pin PR on the new main with a `--force-with-lease` push of its own head, re-reviews and merges it) → comment on #1996. A retired predecessor is marked UNAVAILABLE and its campaign/consumer pins move with the default; a superseded but still-served predecessor keeps its pins (Owner decision 2026-10-13). Ids are parsed ASCII-only in canonical form (no leading zeros); a duplicate id or version fails the catalog closed; `agy --version` is kept only as ASCII `X.Y.Z`. Fallbacks are never changed. Issues it opens use `on_merge: KEEP_OPEN` (#1216 V12: close only after `v12-closable` says 可關閉). Safety: lock file, idempotency key (catalog hash + yaml hash; the same state opens nothing new and an open PR is reused), every effect (Issue, push, PR, merge) is persisted at once and found again on resume (PRs by branch, Issues by a title tag); an in-flight switch resumes before any new decision, re-checks that the new model is still served and re-attests after 24 h while the runtime PR is unmerged (`--clear-pending` is an Owner action after a permanent block), a JSON receipt per run under `~/.local/state/nexus-workforce-autoupdate/runs/`. Exit codes: 0 NOOP/MERGED/DRY_RUN/SKIPPED, 2 BLOCKED, 3 LOCKED. Preview with `python scripts/ops/workforce_model_autoupdate.py --runtime-repo <nexus-runtime clone> --dry-run [--catalog-file <captured agy models stdout>]` (no attestation, git or gh effect). The LaunchAgent template is `scripts/ops/com.nexus.workforce-model-autoupdate.plist.template` (daily); agents must not install it. The tool never reloads the live Gateway: the #2153 auto-deployer deploys the merged pin from main with no Owner activation (#2155).
