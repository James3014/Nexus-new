## 👥 Roles & Responsibilities (BPM)
- **On-Call Engineer**: Authorized to toggle `NEXUS_GATE_BYPASS`, restart Manager, and modify `nodes.json`.
- **Developer**: Authorized to view dashboard/metrics, report anomalies, and query task status.

## 🚨 Incident Response & Emergency Procedures

### 1. Emergency Gate Bypass (Fail-Open)
If the Swarm Manager is unreachable or causing CI blocks, use the following environment variable to bypass all Nexus gates:
```bash
export NEXUS_GATE_BYPASS=true
```
> [!IMPORTANT]
> **Policy**: During the PoC / Shadow Audit stage, the system defaults to **Fail-Open**. All pipelines MUST allow PRs to pass if Nexus is down.

### 2. Restarting the Manager
#### Local Development
1. Signal termination: `pkill -SIGTERM swarm-manager`
2. Backup DB: `cp swarm_tasks.json swarm_tasks.json.bak`
3. Restart: `./swarm-manager -nodes nodes.json`

#### Production (Deployment Aware)
- **Systemd**: `sudo systemctl restart nexus-swarm-manager`
- **Kubernetes**: `kubectl rollout restart deployment/nexus-swarm-manager`

### 3. Cleaning Up Stalled Tasks
If tasks are stuck in `RUNNING` state without progress:
1. The Manager automatically recovers tasks after 30s lease expiry.
2. Check logs for `📢 [EVENT:task.recovered]`.
3. If recovery fails, restart the manager with `-force-recover=true`.

## 📊 Monitoring & SLOs

### 1. Key Metrics (Prometheus)
- **`nexus_tasks_total`**: Count of all dispatched tasks.
- **`nexus_task_latency_seconds`**: Histogram of Selection + Network + Execution time.
- **`nexus_manager_actor_backlog`**: Number of commands waiting in the Actor channel.

| **Latency** | P95 Dispatch Latency | < 500ms |
| **Integrity** | % of tasks successfully recovered | > 95% |

## 🔒 Security & Access Control
- **Repo Access**: Nodes use `NEXUS_SWARM_TOKEN` for mutual TLS/Auth.
- **File System**: Manager only writes to `swarm_tasks.json`.
- **Compute**: Nodes are restricted to `umask 022` and assigned specific working directories.
